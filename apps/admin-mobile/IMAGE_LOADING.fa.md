# بارگذاری تصاویر

اصلاح پس از گزارش کندی نسخهٔ ۰.۲:

- فهرست قبلاً ۲۰ تصویر با اندازهٔ اصلی را در ScrollView درخواست می‌کرد. در توسعهٔ محلی، تصاویر ثابت هم از دامنهٔ آنلاین فروشگاه می‌آمدند.
- اکنون FlatList با batch چهار موردی و پنجرهٔ محدود استفاده می‌شود؛ تصویرهای دور از صفحه هم‌زمان دانلود نمی‌شوند.
- ۱۰۵ مسیر تصویری یکتای کاتالوگ، پیش‌نمایش WebP حداکثر ۳۲۰ پیکسلی داخل assets خود اپ دارند.
  مجموع فایل‌های منبع ۶۷۹۶ KiB و پیش‌نمایش‌ها ۴۲۲ KiB است: کاهش حجم ۹۳٫۸٪، نه ادعای کاهش زمان شبکه به همین نسبت.
- پیش‌نمایش‌ها در native release داخل بستهٔ اپ‌اند؛ در Expo محلی از Metro و در وب از assetهای همان اپ دریافت می‌شوند.
- Expo Image با سیاست memory-disk و recyclingKey استفاده می‌شود. در ویرایش، پیش‌نمایش سبک تا دریافت تصویر بزرگ‌تر نمایش داده می‌شود.
- تصاویر آپلودی جدید با `?width=320` و `?width=640` از بک‌اند دریافت می‌شوند؛ مسیر بدون width همان تصویر اصلی را برمی‌گرداند.
- کش نسخه‌های کوچک در بک‌اند حداکثر ۱۲۸ مورد و ۸ MiB است. URL و ETag هر اندازه جدا و فایل‌ها content-addressed هستند.
- قانون no-store صفحات مدیریت برای assetهای هش‌دار مستثنا شده؛ HTML و داده‌های خصوصی همچنان no-store هستند.
- برای خطای تصویر، حالت تلاش دوباره نمایش داده می‌شود.

برای بازتولید پیش‌نمایش‌ها پس از تغییر فایل‌های کاتالوگ، از ریشهٔ مخزن:

```powershell
& .\backend\.venv-admin\Scripts\python.exe scripts\build-admin-thumbnails.py
```

در CI صحت فایل‌های تولیدشده با `--check` بررسی می‌شود. عکس‌های سفارشی آپلودشده نیاز به بازتولید assets یا انتشار دوبارهٔ اپ ندارند.

اعتبارسنجی: TypeScript، بیلد وب، تست مرورگرِ فهرست مجازی/تصویر بسته‌بندی‌شده، و تست API اندازه/کش و حفظ تصویر اصلی.
زمان واقعی بارگذاری روی شبکه و گوشی کاربر اندازه‌گیری نشده است.
