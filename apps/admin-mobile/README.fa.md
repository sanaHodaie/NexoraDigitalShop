# اپ مدیریتی Nexora Business — نسخهٔ ۰.۲

اپ مستقل React Native / Expo با TypeScript، براساس سند «Nexora Business Intelligence، نسخهٔ ۱.۰».
بک‌اند FastAPI و دیتابیس فروشگاه مشترک‌اند؛ پنل وب و بات مشتری حفظ شده‌اند.
برای اجرای محلی هیچ Docker یا حساب Expo لازم نیست. نصب اولیهٔ npm اینترنت می‌خواهد.

پیش‌نمایش تصاویر کاتالوگ داخل اپ بسته‌بندی شده، فهرست محصولات مجازی و تصاویر آپلودی دارای نسخهٔ کوچک و کش‌اند؛
جزئیات اندازه‌ها و بازتولید در [IMAGE_LOADING.fa.md](IMAGE_LOADING.fa.md).

## قابلیت‌های آماده

- ورود مخصوص مدیران با نشست قابل لغو، کنترل مجوز سمت سرور و خروج از دستگاه.
- ذخیرهٔ نشست در SecureStore در Android/iOS؛ پیش‌نمایش وب فقط در حافظه است و با reload خارج می‌شود.
- داشبورد با آمار واقعی و نمودار واقعی ۳۰روزهٔ درخواست‌های تلگرام.
- هشدار قاعده‌محور برای درخواست جدید و محصول فعال با موجودی کمتر از ۵.
- فهرست عمده/پشتیبانی، فیلتر نوع و وضعیت، صفحه‌بندی، جزئیات مشتری و نشانی.
- تغییر وضعیت رسیدگی و یادداشت داخلی با کنترل نسخه/تعارض.
- اقلام و قیمت توافقی به ریال، اعتبارسنجی اعداد فارسی، بازبینی و تأیید نهایی فاکتور.
- دریافت/اشتراک PDF ذخیره‌شدهٔ مشترک ادمین و مشتری؛ کد رهگیری ۸رقمی و وضعیت صف ارسال تلگرام.
- مشاهده و جست‌وجوی محصولات/موجودی، سفارش‌های سایت، مشتریان و رویدادهای مدیریت.
- رابط فارسی راست‌چین با فونت وزیرمتن، منوی پایین، خطای اتصال و تازه‌سازی دستی/کشیدن صفحه.

- ساخت و ویرایش محصول، تصویر، توضیحات، موجودی، فعال/غیرفعال، فیلتر دسته و نوع محصول.
- افزایش گروهی قیمت با دسته/برند و snapshot تأیید، و قالب/پیش‌نمایش/ثبت XLSX.
- جزئیات کامل سفارش سایت، نشانی و گیرنده، تأیید پرداخت/لغو، PDF با وزیرمتن و کارت گارانتی.
- فعالیت اخیر، فیلتر رویداد و بازهٔ تاریخ UTC، دانلود واقعی XLSX و DOCX تا ۱۰۰۰۰ رکورد فیلترشده.
- خبرنامه و زنگوله با شمارندهٔ خوانده‌نشده و وضعیت خواندن جداگانهٔ هر ادمین در دیتابیس.
- محتوای صفحهٔ اصلی، مقاله/انتشار و تنظیمات فروشگاه؛ تنظیم و تست راهنمای خرید با محصولات واقعی.
- لغو نشست‌های کاربران، تم روشن/تیره/دستگاه با حفظ انتخاب، ظاهر شیشه‌ای و منوی پایین نرم.

خبرنامه هر ۳۰ ثانیه و رویدادها هر ۱۵ ثانیه در اپ باز تازه می‌شوند؛ این اعلان Push هنگام بسته‌بودن برنامه نیست.
ساخت/تغییر نقش از داخل رابط (که در پنل قبلی هم نبود)، Push و بخش‌های مدیریتی ML/LLM هنوز آماده نیستند.
جزئیات و پیش‌نیازهای تمام بخش‌های PDF در [ROADMAP.fa.md](ROADMAP.fa.md) آمده است.

## ۱. پیش‌نیاز ویندوز

- Node.js **22.13 یا جدیدتر از سری 22**، یا **24.3 یا جدیدتر از سری 24**؛ نسخهٔ LTS سازگار نصب کنید.
- Python سازگار با backend و uv؛ همان محیط `.venv-admin` فعلی قابل استفاده است.
- PostgreSQL محلی فعال و تنظیمات معتبر `backend/.env` موجود.
- برای گوشی: Expo Go سازگار با **Expo SDK 58**؛ برای توسعهٔ بومی، Development Build.

```powershell
node --version
npm --version
uv --version
```

## ۲. بک‌اند محلی، بدون Docker

در این نسخه migration **0012** برای خوانده‌شدن اعلان‌ها اضافه شده است؛ بک‌اند قدیمی را متوقف و `start.py` جدید را اجرا کنید.

در ترمینال اول از ریشهٔ مخزن:

```powershell
cd D:\nexoraShop\backend
$env:UV_PROJECT_ENVIRONMENT = ".venv-admin"
uv sync --frozen
```

در `backend/.env`، `ENVIRONMENT=development` و هر دو URL دیتابیس باید به PostgreSQL **محلی** اشاره کنند.
اتصال Neon را برای تست محلی جایگزین نکنید. اگر از عیب‌یابی آنلاین قبلی متغیر موقت مانده است، آن را پاک کنید
تا تنظیمات فایل محلی خوانده شود:

```powershell
Remove-Item Env:MIGRATION_DATABASE_URL -ErrorAction SilentlyContinue
Remove-Item Env:DATABASE_URL -ErrorAction SilentlyContinue
```

برای **پیش‌نمایش وب**، CORS را فقط برای آدرس‌های توسعه فعال کنید؛ اپ بومی به این تنظیم نیاز ندارد:

```powershell
$env:ALLOWED_ORIGINS = '["http://localhost:8081","http://127.0.0.1:8081"]'
uv run --frozen python start.py
```

`start.py` migrationها را اجرا می‌کند و API و Worker را راه می‌اندازد. ترمینال را باز نگه دارید.
اگر قبلاً بک‌اند روی پورت 8000 روشن است، آن را با Ctrl+C متوقف و نسخهٔ جدید را اجرا کنید.

در ترمینال دوم:

```powershell
curl.exe --noproxy "*" --max-time 10 http://localhost:8000/health
```

انتظار: `{"status":"ok"}`.
در محیط development و بدون `REDIS_URL`، محدودکنندهٔ محلی استفاده می‌شود؛ تنظیمات production را تغییر ندهید.
اگر `REDIS_URL` تنظیم است، همان سرویس باید در دسترس باشد.

## ۳. حساب ادمین آزمایشیِ محلی

حساب آنلاین و لوکال خودکار همگام نمی‌شوند. برای ساخت یا تنظیم رمز یک ادمین محلی:

```powershell
cd D:\nexoraShop\backend
$env:UV_PROJECT_ENVIRONMENT = ".venv-admin"
uv run --frozen python -m app.setup_local_admin adminpannel@nexora.com
```

رمز ۱۲ تا ۱۲۸ کاراکتری را دو بار وارد کنید؛ تایپ نمایش داده نمی‌شود. این دستور حساب محلی موجود را
به‌روزرسانی یا حساب جدید ایجاد می‌کند، نشست‌های قبلی همان حساب را لغو و مجوز مدیریت را تنظیم می‌کند.
روی host غیرمحلی یا محیط غیرdevelopment اجرا نمی‌شود. پس از پیام `Local admin ready` از همین مشخصات استفاده کنید.
اگر کاربر مهاجرت اجازهٔ ساخت نقش/کاربر برنامه را ندارد، اتصال مالک محلی و grants را طبق راهنمای بک‌اند اصلاح کنید؛
کاربر runtime را superuser نکنید.

## ۴. نصب اپ و تست روی مرورگر لپ‌تاپ

در ترمینال دوم:

```powershell
cd D:\nexoraShop\apps\admin-mobile
npm ci --no-audit --no-fund
Copy-Item .env.example .env
notepad .env
```

در فایل اپ فقط آدرس عمومی API است، نه کلید یا رمز:

```dotenv
EXPO_PUBLIC_API_URL=http://localhost:8000
APP_VARIANT=development
```

سپس:

```powershell
npm run web
```

اگر پرسید پورت 8081 را تغییر دهد، برنامهٔ قبلی را ببندید یا origin پورت جدید را در CORS بک‌اند هم اضافه کنید.
برای تست مرورگر لپ‌تاپ، مشخصاً `http://localhost:8081` را باز کنید تا با CORS تنظیم‌شده مطابقت داشته باشد.
روی «بررسی اتصال» بزنید و با ادمین مرحلهٔ قبل وارد شوید.
نسخهٔ مرورگر برای تست رابط است؛ جای نسخهٔ بومی و تست SecureStore/اشتراک‌گذاری گوشی را نمی‌گیرد.

## ۵. تست روی Android Emulator یا گوشی واقعی

### شبیه‌ساز Android روی همان لپ‌تاپ

در `.env` اپ:

```dotenv
EXPO_PUBLIC_API_URL=http://10.0.2.2:8000
APP_VARIANT=development
```

شبیه‌ساز Android Studio را روشن کنید و از پوشهٔ اپ اجرا کنید:

```powershell
npm start -- --go
```

کلید `a` را بزنید. پارامتر `--go` استفاده از Expo Go را مشخص می‌کند؛ بدون آن، در صورت نصب dev-client
ممکن است CLI دنبال Development Build بگردد. نسخهٔ Expo Go باید با SDK 58 هماهنگ باشد.

### گوشی واقعی روی Wi-Fi مشترک

1. با `ipconfig` آدرس IPv4 آداپتور Wi-Fi لپ‌تاپ را پیدا کنید؛ مثلاً `192.168.1.100`.
2. `.env` اپ: `EXPO_PUBLIC_API_URL=http://192.168.1.100:8000` (IP واقعی خودتان).
3. بک‌اند فعلی با `start.py` روی `0.0.0.0:8000` گوش می‌دهد؛ در فایروال فقط برای شبکهٔ Private
   اجازهٔ دسترسی Python/پورت 8000 و Metro بدهید. فایروال را کامل خاموش نکنید.
4. در مرورگر گوشی `http://IP-LAPTOP:8000/health` را باز کنید؛ باید `ok` برگردد.
5. در پوشهٔ اپ `npm start -- --go` و QR را با Expo Go باز کنید.

`localhost` در گوشی یعنی خود گوشی؛ از آن برای بک‌اند لپ‌تاپ استفاده نکنید.
تغییر `.env` نیازمند restart کردن Metro است؛ در صورت کش قدیمی `npm start -- --go --clear`.
VPN یا جداسازی دستگاه‌های Wi-Fi ممکن است ارتباط شبکهٔ محلی را مختل کند.
Expo Tunnel فقط Metro را تونل می‌کند؛ دسترسی بک‌اند را خودکار فراهم نمی‌کند.

## ۶. سناریوی تست واقعی عمده و فاکتور

1. بات را به **همین بک‌اند آزمایشی** وصل کنید: `NEXORA_API_URL=http://localhost:8000`.
2. کلید `TELEGRAM_BOT_API_KEY` در بات و بک‌اند یکسان باشد. برای ارسال واقعی، `TELEGRAM_BOT_TOKEN`
   در بک‌اند و `BOT_TOKEN` در بات، متعلق به همان بات باشند؛ مقادیر را در فایل اپ نگذارید.
3. بهتر است بات آزمایشی جدا داشته باشید. برای یک بات، polling محلی و آنلاین را هم‌زمان اجرا نکنید.
4. از بات یک درخواست ثبت کنید؛ در اپ «درخواست‌ها → تازه‌سازی» نام، تلفن، اقلام و نشانی را تطبیق دهید.
5. یادداشت داخلی و وضعیت را ذخیره کنید؛ یادداشت نباید به مشتری نمایش داده شود.
6. قیمت توافقی هر قلم را **به ریال** وارد کنید؛ «بازبینی» و سپس «تأیید نهایی» را بزنید.
7. کد رهگیری، PDF و وضعیت ارسال را بررسی کنید. «در صف» به معنی ارسال موفق نیست.
8. Worker باید روشن و به Telegram دسترسی داشته باشد. روی ویندوز، در صورت نیاز پروکسی HTTPS را
   در همان ترمینال اجرای بک‌اند تنظیم کنید و `NO_PROXY` را برای localhost نگه دارید.
9. PDF دریافتی در اپ و تلگرام باید همان فاکتور باشد؛ تأیید فاکتور پرداخت را تأیید نمی‌کند.
10. با حساب بدون مجوز، نشست منقضی، اینترنت قطع و تأیید هم‌زمان از دو دستگاه هم تست کنید.

اگر بات هنوز به Render وصل است و اپ به localhost، درخواست‌های آن در اپ محلی دیده نمی‌شوند.
برای تست بدون تلگرام می‌توانید ابتدا ورود، داشبورد، کاتالوگ و صفحه‌های خالی را بررسی کنید؛
آزمون خودکار بک‌اند سناریوی فاکتور را با دادهٔ آزمایشی و بدون ارسال بیرونی پوشش می‌دهد.

## ۷. تست‌ها و بیلد

از پوشهٔ اپ:

```powershell
npm run typecheck
npm test
npm run export:web
```

خروجی وب production برای API HTTPS است؛ اجرای توسعهٔ محلی را با `npm run web` انجام دهید.
برای بررسی bundle بومی بدون Android SDK/Mac:

```powershell
npx expo export --platform android --output-dir dist-android
npx expo export --platform ios --output-dir dist-ios
```

این دستورها APK/IPA نمی‌سازند و جای تست دستگاه را نمی‌گیرند.
پروفایل‌های EAS در `eas.json` آماده‌اند؛ برای Development Build باید حساب Expo و تنظیم build داشته باشید.
قبل از preview/production، `EXPO_PUBLIC_API_URL` را در محیط build به HTTPS سرور موردنظر تنظیم کنید.
بیلد Android روی ویندوز با Android SDK ممکن است؛ شبیه‌ساز و build محلی iOS به macOS نیاز دارند.
قیمت و دسترسی سرویس‌های build و انتشار را هنگام انتشار بررسی کنید.

## امنیت و انتشار

### چک‌لیست تست امکانات ۰.۲

1. **محصولات:** دستهٔ صوتی و سپس نوع هندزفری را انتخاب کنید. عکس باید سمت راست باشد؛ یک محصول را ویرایش، ذخیره و در سایت محلی بررسی کنید.
2. **فعال/غیرفعال:** پس از تأیید، محصول از کاتالوگ مشتری پنهان/نمایان می‌شود و سابقهٔ سفارش باقی می‌ماند.
3. **قیمت گروهی:** دسته و برند و درصد را انتخاب کنید؛ ابتدا پیش‌نمایش و سپس تأیید را بزنید. تغییر هم‌زمان داده باید نیاز به پیش‌نمایش تازه بدهد.
4. **اکسل:** قالب را دانلود و با شناسهٔ جدید پر کنید؛ انتخاب فایل به‌تنهایی ثبت نمی‌کند. خطاهای ردیف را اصلاح و سپس تأیید کنید.
5. **سفارش سایت:** ابتدا نام مشتری را ببینید، جزئیات را باز کنید و نشانی/کد پستی/اقلام را با سفارش تطبیق دهید؛ PDF و در سفارش پرداخت‌شده، کارت گارانتی را دانلود کنید.
6. **رویدادها:** نوع و تاریخ میلادی/UTC را فیلتر و XLSX/DOCX را باز کنید؛ خروجی تمام رویدادهای همان فیلتر است، نه فقط صفحهٔ جاری.
7. **خبرنامه:** برای تست محلی، فروشگاه را هم از ریشه با `npm run dev` روی 3000 اجرا کنید و با یک حساب محلی عضو خبرنامه شوید.
   در اپ باز تا ۳۰ ثانیه بعد شمارنده بالا می‌رود؛ بازکردن خبرنامه اعلان‌های دریافت‌شده را خوانده‌شده می‌کند. وضعیت هر ادمین مستقل است.
8. **تم:** از حساب، روشن/تیره/دستگاه را انتخاب کنید؛ بعد از بازکردن دوباره، انتخاب باید حفظ شده باشد.
9. **محتوا و راهنما:** تغییر آزمایشی را ذخیره کنید، سایت را تازه کنید و سپس مقدار قبلی را برگردانید. تست راهنمای خرید از کاتالوگ واقعی و تنظیمات ذخیره‌شده استفاده می‌کند.

عضویت/سفارش در سایت آنلاین به دیتابیس Neon می‌رود و در اپ متصل به PostgreSQL محلی دیده نمی‌شود؛ دو طرف تست باید به یک بک‌اند متصل باشند.

### نسخهٔ آنلاین در Vercel فعلی

بعد از دریافت این commit در `main` و Deploy موفق هر دو سرویس:

```text
https://nexora-digital-shop.vercel.app/business
```

بیلد ریشهٔ Vercel اکنون `npm run build:vercel` است؛ فروشگاه و پنل قدیمی را می‌سازد، وابستگی‌های قفل‌شدهٔ
اپ را نصب و خروجی Expo را زیر `dist/business` قرار می‌دهد. آدرس assetها و مسیرهای مستقیم اپ با `/business`
ساخته می‌شوند. مسیرهای API از همان `/api` به Render می‌روند؛ برای این نسخهٔ وب CORS جدا لازم نیست.
Root Directory پروژهٔ Vercel باید ریشهٔ مخزن باقی بماند. اجرای `npm run build` به‌تنهایی همچنان فقط فروشگاه/پنل قبلی را می‌سازد.

بک‌اند Render هم باید کد جدید و migration 0012 را اجرا کرده باشد. برای بررسی عمومی، این آدرس باید JSON با `mobileVersion: 2` بدهد:

```text
https://nexora-digital-shop.vercel.app/api/mobile/health
```

**نام کاربری، ایمیل حساب ادمین آنلاین است**؛ هیچ رمز پیش‌فرضی داخل برنامه نیست.
رمز ادمین محلی به Neon منتقل نمی‌شود. برای حساب آنلاین موجود، می‌توانید رمز دلخواه را با ابزار اپراتور تنظیم کنید:

```powershell
cd D:\nexoraShop\backend
$env:UV_PROJECT_ENVIRONMENT = ".venv-admin"
$dbSecret = Read-Host "Paste Render MIGRATION_DATABASE_URL" -AsSecureString
$env:MIGRATION_DATABASE_URL = [System.Net.NetworkCredential]::new("", $dbSecret).Password
uv run --frozen python -m app.provision_admin adminpannel@nexora.com --set-password
Remove-Item Env:MIGRATION_DATABASE_URL
Remove-Variable dbSecret
```

رمز جدید ۱۲ تا ۱۲۸ کاراکتری دو بار مخفی دریافت می‌شود؛ حساب باید از قبل در **همان دیتابیس آنلاین** ثبت شده باشد.
دستور مجوز مدیریت را تنظیم، رمز را hash و نشست‌های قبلی حساب را لغو می‌کند. رشتهٔ اتصال یا رمز را در گیت، آرگومان دستور یا چت قرار ندهید.
این اتصال از لپ‌تاپ به Neon به DNS/شبکهٔ سالم نیاز دارد؛ اگر خطای `getaddrinfo` گرفتید، تغییر رمز انجام نشده است.
می‌توان همین ابزار را در یک محیط اجرایی مجازِ متصل به دیتابیس آنلاین اجرا کرد؛ ارتقای Render برای نسخهٔ محلی اپ لازم نیست.

برای native release همچنان `EXPO_PUBLIC_API_URL=https://nexora-api-s2q3.onrender.com` را در محیط build تنظیم کنید.
متغیر `EXPO_PUBLIC_WEB_SAME_ORIGIN=1` و پیشوند `/business` را اسکریپت وب خودش تنظیم می‌کند؛ آن‌ها را برای گوشی فعال نکنید.

- نشست‌ها در سرور به صورت hash ذخیره می‌شوند و همان idle timeout/لغو نشست فعلی را دارند.
- Bearer فقط برای API مدیریتی و نشست موبایل پذیرفته می‌شود؛ مسیرهای مرورگر CSRF خود را حفظ می‌کنند.
- بعد از خروج، کش داده‌های حساب پاک می‌شود؛ اطلاعات مشتری در storage دائمی اپ ذخیره نمی‌شود.
- فایل فاکتور بومی بعد از پایان اشتراک‌گذاری از کش موقت پاک می‌شود؛ نسخهٔ ذخیره‌شدهٔ کاربر باقی می‌ماند.
- گزارش‌ها حاوی دادهٔ مجاز مدیریتی‌اند؛ فایل دانلودشده را ادمین باید در جای امن نگه دارد. خروجی اکسل فرمول ورودی کاربران را اجرا نمی‌کند.
- HTTP فقط برای localhost/شبکهٔ خصوصی در development مجاز است؛ نسخهٔ release به HTTPS نیاز دارد.
- ساخت اپ یا commit کردن فایل، رمز حساب آنلاین را تغییر نمی‌دهد و خطای ورود آنلاین قبلی هنوز باید جداگانه تشخیص داده شود.
- پنل قدیمی تا تکمیل قابلیت‌ها و تأیید تست‌های مهاجرت حذف نمی‌شود.
