# ربات تلگرام نکسورا — اجرا و تست

این پوشه نسخهٔ یکپارچه‌شدهٔ ZIP ارسالی با بک‌اند همین مخزن است.
فعلاً ربات چتی است؛ مینی‌اپ و بازطراحی گرافیکی مرحلهٔ بعد از تست دستی شماست.

## امکانات فعلی

- منوی فارسی/انگلیسی و ذخیرهٔ زبان، محصولات، جست‌وجو، جزئیات و مقایسهٔ حداکثر سه محصول.
- قیمت مطابق `src/lib/money.js`: قیمت پایهٔ API × ۶۰۰۰۰۰، با نمایش ریال.
- دریافت دوبارهٔ قیمت و موجودی هنگام بازکردن جزئیات و نمایش مقایسه.
- اتصال اختیاری حساب سایت به تلگرام با لینک یک‌بارمصرف ۱۰ دقیقه‌ای؛ مشاهده و قطع اتصال در سایت.
- فرمان‌های `/start`، `/help`، `/ping`، `/language`، `/cancel` و `/link`.
- `/link` کاربر را به حساب سایت راهنمایی می‌کند؛ رمز سایت یا کد ورود در چت گرفته نمی‌شود.
- عملیات حساب فقط در چت خصوصی انجام می‌شود. سفارش‌گذاری در چت، اعلان سفارش و پرداخت پیاده‌سازی نشده‌اند.

## ۱. مشخصات بات را پیدا کنید

از کسی که بات را ساخته این دو مورد را بگیرید:

1. نام کاربری عمومی، مثل `@YourShopBot`.
2. توکن BotFather، فقط از راه امن و برای قراردادن در `.env` محلی یا تنظیمات امن میزبان؛ در چت، گیت یا اسکرین‌شات نفرستید.

اگر مالک بات هستید، در تلگرام `@BotFather` → `/mybots` → انتخاب بات، نام کاربری و API Token را بررسی کنید.
از سازنده بخواهید نسخهٔ قبلی بات را موقتاً متوقف کند. برای یک توکن فقط یک polling process اجرا کنید.
این برنامه webhook موجود را خودکار حذف نمی‌کند و پیام‌های در صف را دور نمی‌ریزد.

## ۲. نصب بات (Windows PowerShell)

ابتدا مخزن را با تاریخچهٔ فعلی دریافت/به‌روز کنید. Node و uv باید نصب باشند.

```powershell
cd D:\nexoraShop\telegram_bot
uv sync --frozen
Copy-Item .env.example .env
notepad .env
```

اگر `.env` از قبل دارید، آن را دوباره کپی و بازنویسی نکنید. مقدارها:

```dotenv
BOT_TOKEN=توکن_واقعی_فقط_در_فایل_محلی
NEXORA_API_URL=http://localhost:8000
PRODUCTS_PATH=/api/products
PRODUCT_DETAIL_PATH=/api/products/{id}
FRONTEND_URL=http://localhost:3000
PRICE_SUFFIX=" ریال"
PAGE_SIZE=5
DATA_DIR=./data
TELEGRAM_BOT_API_KEY=
PROXY_URL=
```

برای محصولات و جست‌وجو، کلید داخلی بک‌اند لازم نیست. `BOT_TOKEN` همیشه برای اجرای تلگرام لازم است.
`NEXORA_API_URL` باید آدرس **بک‌اند FastAPI** باشد؛ دامنهٔ فرانت‌اند فقط وقتی درست است که مسیر API را پروکسی کند.
برای حساب متصل، ربات باید مستقیم به آدرس بک‌اند با مسیر `/internal/telegram/link-confirmations` دسترسی داشته باشد؛
این مسیر زیر `/api` نیست و از پروکسی معمول Vite عبور نمی‌کند.

در Linux نیز از همین پوشه `uv sync --frozen` و `uv run --frozen python ...` اجرا می‌شود.
پراگسی اختیاری خودتان را در `PROXY_URL` بگذارید. تنظیمات proxy و CA محیط ابری نیز رعایت می‌شوند؛ TLS را غیرفعال نکنید.

## ۳. اجرای سایت و بک‌اند

از ریشهٔ مخزن، روش سادهٔ مستندشدهٔ پروژه:

```powershell
cd D:\nexoraShop
docker compose up -d --build
```

این فرمان PostgreSQL، Redis، API/worker و Vite را اجرا می‌کند. از حذف volumeها خودداری کنید.
برای نصب غیر Docker، راهنمای `backend/LOCAL_SETUP.fa.md` را دنبال کنید؛ بک‌اند با
`uv run --frozen python start.py` و فرانت‌اند با `npm ci` سپس `npm run dev` اجرا می‌شود.
`start.py` مهاجرت `0009` و دسترسی نقش محدود runtime به جدول‌های اتصال را اعمال می‌کند.
برای اجرای migration جداگانه، `backend/scripts/grants.sql` هم باید پس از migration اجرا شود.

## ۴. فعال‌کردن اتصال حساب (اختیاری برای کاتالوگ)

یک کلید تصادفی بسازید؛ مقدار تولیدشده را فقط در تنظیمات محلی نگه دارید:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

در `telegram_bot/.env`:

```dotenv
TELEGRAM_BOT_API_KEY=کلید_تصادفی_۳۲_کاراکتر_یا_بیشتر
```

برای بک‌اند غیر Docker، در `backend/.env` و برای Docker Compose در `.env` **ریشهٔ مخزن** قرار دهید:

```dotenv
TELEGRAM_BOT_API_KEY=همان_کلید_داخلی_بات
TELEGRAM_BOT_USERNAME=YourShopBot
```

نام کاربری را بدون `@` و بدون URL بنویسید. کلید داخلی با توکن BotFather فرق دارد.
بک‌اند را restart کنید. در Compose: `docker compose up -d --build api`.
هیچ‌کدام را در متغیر `VITE_*` قرار ندهید.

لینک از نشست واردشدهٔ سایت ساخته می‌شود، در دیتابیس فقط هش آن می‌ماند و تأییدش به کلید داخلی نیاز دارد.
هر حساب سایت و حساب تلگرام فقط یک اتصال دارند. صدور لینک جدید قبلی را باطل می‌کند.
این اتصال مجوز خواندن سفارش یا انجام خرید از طریق چت به ربات نمی‌دهد.

## ۵. بررسی پیش از اجرا

```powershell
cd D:\nexoraShop\telegram_bot
uv run --frozen python -m pytest -q
uv run --frozen python preflight.py
uv run --frozen python preflight.py --telegram
```

- دستور اول تست‌های خودکار بدون اینترنت تلگرام است.
- دستور دوم با HTTP واقعی سلامت، فهرست غیرخالی و جزئیات محصول را بررسی می‌کند.
- دستور سوم علاوه بر بک‌اند، `getMe` و وضعیت webhook را از تلگرام می‌خواند و نام کاربری واقعی را نمایش می‌دهد؛ هیچ پیامی نمی‌فرستد.
- خطای دستور سوم یعنی هنوز اجازه نداریم اتصال واقعی را تأییدشده بدانیم؛ توکن، شبکه و اجرای نسخهٔ قبلی را بررسی کنید.

سپس در همان پوشه:

```powershell
uv run --frozen python main.py
```

ترمینال باید روشن بماند. `Ctrl+C` برنامه را متوقف می‌کند. برای اجرای دائمی باید یک process همیشه‌روشن روی میزبان داشته باشید؛ هاست استاتیک فرانت‌اند، polling bot را اجرا نمی‌کند.

## ۶. چک‌لیست تست دستی شما

1. چت **خصوصی** بات را باز کنید، `/start` بزنید؛ منو باید نمایش داده شود.
2. `/ping` بزنید؛ بک‌اند باید در دسترس گزارش شود.
3. محصولات را باز کنید، صفحهٔ بعد و قبل را امتحان کنید و یک محصول را باز کنید؛ نام، قیمت ریالی و موجودی را با سایت مقایسه کنید.
4. یک عبارت واقعی مثل نام محصول را جست‌وجو کنید؛ عبارت بی‌نتیجه نیز باید پیام مناسب بدهد.
5. سه محصول را برای مقایسه انتخاب کنید؛ چهارمی نباید اضافه شود. در صفحهٔ بعد، دکمه‌ها باید همچنان انتخاب مقایسه باشند.
6. زبان را انگلیسی کنید، منو را بررسی و بات را restart کنید؛ زبان کاربر باید حفظ شود.
7. در سایت وارد شوید → «حساب کاربری» → «اطلاعات شخصی» → «اتصال تلگرام» → «دریافت لینک اتصال».
8. لینک را باز کنید و در تلگرام Start را بزنید؛ فقط بعد از پاسخ بک‌اند باید تأیید اتصال ببینید.
9. به سایت برگردید و «بررسی وضعیت اتصال» را بزنید؛ وضعیت باید متصل باشد.
10. استفادهٔ دوباره از همان لینک باید رد شود. لینک تازه پس از ۱۰ دقیقه هم باید رد شود.
11. در سایت «قطع اتصال تلگرام» را بزنید و وضعیت را دوباره بررسی کنید.
12. بک‌اند را موقتاً متوقف کنید؛ `/ping` و محصولات باید خطای قابل‌فهم بدهند. سپس بک‌اند را دوباره روشن کنید.

برای گزارش نتیجه، فقط شمارهٔ مرحله، رفتار دیده‌شده و متن خطای بدون توکن را بفرستید.
نام کاربری عمومی قابل‌ارسال است؛ فایل `.env` و لینک یک‌بارمصرف را نفرستید.

## شواهد تست و محدودیت

تست‌های واحد بات، dispatcher با ساختار واقعی Update و حمل‌ونقل شبیه‌سازی‌شدهٔ تلگرام،
قرارداد کلاینت بات با FastAPI، و امنیت لینک‌ها روی PostgreSQL بررسی می‌شوند.
`backend/tests/security/test_telegram.py` مصرف مجدد، انقضا، تعارض حساب‌ها، CSRF و رقابت تأیید هم‌زمان را پوشش می‌دهد.
این تست‌ها جای اتصال زنده به Telegram API و تست دستی شما را نمی‌گیرند.
در محیط بررسی، BotFather token و نام کاربری ارائه نشده‌اند؛ polling و تحویل پیام واقعی تأیید نشده‌اند.

تست رابط حساب در Chromium با API شبیه‌سازی‌شده (پس از اجرای Vite):

```powershell
$env:NEXORA_CHROME = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
node scripts/check-telegram.mjs
```

این دستور از **ریشهٔ مخزن** اجرا می‌شود؛ وضعیت اتصال واقعی تلگرام را تغییر نمی‌دهد.
