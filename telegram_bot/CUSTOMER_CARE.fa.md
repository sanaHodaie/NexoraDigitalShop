# تست بات ارتباط با مشتری و درخواست عمده

منوی اصلی جدید: «درخواست خرید عمده»، «درخواست پشتیبانی»، «سؤالات متداول»، «پیگیری درخواست‌ها» و تغییر زبان.
نمایش کاتالوگ و مقایسه دیگر محور منو نیستند؛ مسیرهای قدیمی برای سازگاری باقی مانده‌اند.
درخواست عمده یک استعلام است؛ حداقل تعداد تجاری، قیمت قطعی، پرداخت و زمان تحویل خودکار تعریف نشده‌اند.

## ۱. دریافت و آماده‌سازی

بات محلی را با Ctrl+C متوقف کنید. از ریشهٔ همان نسخهٔ تمیز مخزن:

```powershell
git pull --ff-only origin main
cd telegram_bot
uv sync --frozen
```

اگر دوستتان تغییرات محلی دارد، آن‌ها را پاک/reset نکنید؛ مانند قبل از نسخهٔ تمیز جدا استفاده کنید.

## ۲. اتصال امن بات به پنل

برای ثبت واقعی درخواست، متغیر `TELEGRAM_BOT_API_KEY` باید در **بک‌اند Render** و **محیط اجرای بات** دقیقاً یکسان و حداقل ۳۲ کاراکتر باشد.
این کلید با توکن BotFather فرق دارد. اگر از قبل کلید مشترک معتبر دارید، همان را حفظ کنید.
اگر ندارید، روی کامپیوتر خودتان کلید بسازید:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

خروجی را فقط در تنظیمات امن Render و `telegram_bot/.env` محلی یا تنظیمات امن میزبان Webhook قرار دهید؛ در چت/گیت نفرستید.
`NEXORA_API_URL` باید دامنهٔ مستقیم بک‌اند Render باشد؛ مسیرهای `/internal/telegram/*` از پروکسی معمول فرانت‌اند عبور نمی‌کنند.
BOT_TOKEN فقط برای بات است و لازم نیست روی بک‌اند فروشگاه قرار گیرد.

## ۳. انتشار بک‌اند و پنل

- Render باید نسخهٔ جدید را Deploy کند و وضعیت Live شود. `start.py` مهاجرت `0010` و دسترسی جدول `customer_requests` را اعمال می‌کند.
- اگر مهاجرت خودکار را خاموش کرده‌اید، مالک مهاجرت باید Alembic و سپس `scripts/grants.sql` به‌روزشده را اجرا کند؛ دیتابیس/volume را پاک نکنید.
- فرانت‌اند Vercel نیز باید نسخهٔ جدید را Deploy کند تا بخش پنل اضافه شود.
- مدیر با دسترسی `orders:read` درخواست‌ها را می‌بیند؛ ویرایش وضعیت/یادداشت به `orders:cancel` (دسترسی رسیدگی فعلی سفارش‌ها) نیاز دارد. نقش صرفاً خواندنی حق تغییر ندارد.

## ۴. اجرا و تست محلی بات

```powershell
uv run --frozen python main.py
```

فقط یک نسخهٔ polling برای همین توکن روشن باشد. اگر Webhook فعال است، مطابق DEPLOYMENT.fa.md آن را مدیریت کنید؛ هم‌زمان main.py را اجرا نکنید.

در چت خصوصی بات:

1. `/start` و سپس «شروع» را بزنید؛ منوی خدمات مشتری باید باز شود، بدون نیاز به دریافت کاتالوگ.
2. «سؤالات متداول» را باز و پاسخ‌های عمده، قیمت و ارسال را بررسی کنید.
3. «درخواست خرید عمده» را بزنید و نام، شماره تماس، شرکت/فروشگاه، اقلام، تعداد کل، شهر، نشانی و توضیحات را وارد کنید. برای شرکت و توضیحات می‌توانید `-` بفرستید.
4. شماره و تعداد فارسی هم پذیرفته می‌شوند. تعداد صفر یا تلفن نامعتبر باید رد شود.
5. خلاصه را بررسی کنید؛ قبل از «تأیید و ارسال» چیزی در پنل ثبت نمی‌شود.
6. تأیید کنید؛ شمارهٔ پیگیری فقط پس از پاسخ موفق سرور نمایش داده می‌شود.
7. در پنل سایت به `/admin#customer-requests` بروید و وارد حساب مدیر شوید. از منو «درخواست‌های تلگرام و عمده» را باز کنید.
8. نام مشتری، شناسه/نام کاربری تلگرام، تلفن، اقلام، تعداد و نشانی را با فرم مقایسه کنید.
9. وضعیت را به «تماس گرفته شد» تغییر دهید، یک یادداشت داخلی بنویسید و ذخیره کنید.
10. در بات «پیگیری درخواست‌ها» را بزنید؛ وضعیت جدید باید دیده شود. یادداشت داخلی، تلفن و نشانی در پاسخ پیگیری عمومی نمایش داده نمی‌شوند.
11. با یک حساب تلگرام دیگر، پیگیری را امتحان کنید؛ درخواست حساب اول نباید نمایش داده شود.
12. یک فرم را قبل از ارسال با `/cancel` کنار بگذارید. هنگام خطای ارتباطی، پیام موفقیت نباید نمایش داده شود؛ تأیید مجدد همان فرم برای جلوگیری از ثبت تکراری شناسهٔ ثابت دارد.

## ۵. تست صفحهٔ خطا

- روی سایت یک مسیر ناموجود مثل `/missing-test-page` باز کنید؛ صفحهٔ تصویردار باید نمایش داده شود.
- `/category/not-a-category` و `/magazine/not-an-article` نیز همین طراحی را دارند.
- در موبایل و حالت روشن/تیره، تصویر وسط، متن، دکمهٔ خانه و لینک پشتیبانی را بررسی کنید.
- «بازگشت به خانه» و «گشت‌وگذار در فروشگاه» باید کار کنند. خطای رندر صفحات نیز نسخهٔ «کمی مکث» و دکمهٔ تلاش دوباره دارد.
- این fallback در SPA ارائه می‌شود؛ وضعیت HTTP واقعی 404 در میزبانی استاتیک با rewrite جداست و در این تغییر ادعا نشده است.

تست مرورگر محلی (API پنل شبیه‌سازی می‌شود؛ بک‌اند جداگانه با PostgreSQL تست شده):

```powershell
$env:NEXORA_CHROME='C:/Program Files/Google/Chrome/Application/chrome.exe'
node scripts/check-customer-care.mjs
```

این دستور از ریشهٔ مخزن و با Vite روشن اجرا می‌شود.
