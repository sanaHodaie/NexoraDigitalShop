# بارگذاری محصولات

فرانت‌اند روی Vercel است و `/api/products` به Render بازنویسی می‌شود.
Render Free پس از ۱۵ دقیقه بدون درخواست می‌خوابد و بیدارشدن آن حدود یک دقیقه
طول می‌کشد. کش، زمان انتظار بسیاری از بازدیدها را کم می‌کند ولی اولین درخواست
بدون کش همچنان به پاسخ سرور نیاز دارد.

## رفتار جدید

- فقط پاسخ موفق GET `/api/products` عمومی و قابل کش است: مرورگر ۳۰ ثانیه،
  Vercel ۶۰ ثانیه تازه و سپس تا یک ساعت قابل نمایش هم‌زمان با بازخوانی از مبدا.
  در نتیجه قیمت و موجودی نمایش‌داده‌شده ممکن است قدیمی باشد؛ سبد خرید و سفارش
  همچنان اطلاعات معتبر دیتابیس را بررسی می‌کنند.
- فعال‌سازی کش بازنویسی در `vercel.json` برای همین مسیر انجام شده است. TTL در
  بک‌اند تعریف می‌شود؛ در Vercel آن را به کل `/api` تعمیم ندهید.
- اطلاعات حساب، کوکی‌ها، CSRF، خطاها و درخواست‌های تغییردهنده کش عمومی ندارند.
- مرورگر فقط آخرین فهرست عمومی دریافت‌شده از API را در localStorage تا ۲۴ ساعت
  نگه می‌دارد؛ پس از ۶۰ ثانیه، کارت‌ها فوراً نمایش داده و اطلاعات در پس‌زمینه
  به‌روزرسانی می‌شوند. وضعیت به‌روزرسانی/شکست آن در صفحه نشان داده می‌شود.
  اطلاعات کاربر یا توکن وارد این کش نمی‌شود و دادهٔ نمونه جایگزین API نشده است.
- درخواست محصولات بدون کوکی ارسال می‌شود و پس از ۷۰ ثانیه به وضعیت قابل تلاش
  مجدد می‌رسد؛ فهرست ذخیره‌شده در صورت شکست شبکه حفظ می‌شود.

## انتشار و بررسی

هر دو بک‌اند Render و فرانت‌اند Vercel باید با تغییرات جدید منتشر شوند.
پس از انتشار موفق، `/api/products` را دو بار بدون Disable cache در DevTools
باز کنید و `x-vercel-cache` را برای HIT یا STALE بررسی کنید. اولین بار ممکن است
MISS باشد؛ کش Vercel منطقه‌ای است و نگهداری آن تضمین‌شده نیست.
برای حذف فوری محصول/قیمت از CDN، کش دارای تگ `nexora-catalog` را از ابزارهای
مدیریت Vercel پاک کنید. کش مرورگر مستقل است؛ اعتبار نهایی خرید در بک‌اند است.

اگر `/health` یا `/api/products` پس از بیدارشدن هم پاسخ نمی‌دهد، Logs و Events
Render و اتصال دیتابیس/Redis باید بررسی شود؛ اصلاح فرانت‌اند خرابی سرور را
برطرف نمی‌کند. حذف تأخیر اولین بازدید نیازمند میزبانی بک‌اند همیشه‌روشن است.

منابع:
- [Render Free](https://render.com/docs/free#spinning-down-on-idle)
- [Vercel external rewrite caching](https://vercel.com/docs/routing/rewrites#caching-rewrites-to-external-origins)
- [Vercel cache criteria](https://vercel.com/docs/caching/cdn-cache#cacheable-response-criteria)

## بهینه‌سازی تصاویر و فونت — ۱۶ نوامبر ۲۰۲۶

- ۱۲۳ منبع محلی، نسخه‌های ۳۲۰/۶۴۰/۹۶۰ پیکسلی WebP دارند. مرورگر با `srcset/sizes` نسخهٔ مناسب عرض و تراکم نمایشگر را می‌گیرد. اصل تصویر و alpha حفظ شده‌اند؛ عکس جزئیات/hero اصلی برای وضوح بیشتر باقی می‌ماند.
- اندازه‌های جدید فقط به asset ثبت‌شده یا مسیر معتبر رسانهٔ API اعمال می‌شوند؛ URL سفارشی فروشنده و query آن بازنویسی عمومی نمی‌شوند. تصویر آپلودشدهٔ معتبر از thumbnailهای ۳۲۰/۶۴۰ موجود API استفاده می‌کند.
- عکس‌های فوتر دیگر پیش از رسیدن کاربر دانلود نمی‌شوند. کارت‌ها، پیشنهادها، سبد، جست‌وجو، مقایسه و فهرست علاقه‌مندی، عکس متناسب با اندازهٔ نمایش می‌گیرند. تصاویر انتخاب مجموعه و مقاله نیز از نسخهٔ بهینه استفاده می‌کنند.
- وزیرمتن WOFF2 از خود سایت می‌آید و regular پیش‌بارگذاری می‌شود. دو فونت در مجموع از ۲۵۴٬۱۴۸ به ۱۰۴٬۴۲۰ بایت رسیده‌اند. stylesheet مسدودکنندهٔ Google Fonts از فروشگاه حذف شده؛ ورود اختیاری گوگل همچنان مستقل کار می‌کند.
- فایل‌های تصویری جدید content-addressed هستند و کش immutable دارند؛ اطلاعات حساب، CSRF و پاسخ خصوصی عمومی‌سازی نشده‌اند. تغییر روش تصویر، دادهٔ قیمت/موجودی API را با seed یا دادهٔ حدسی جایگزین نکرده است.

### روش اندازه‌گیری

نسخهٔ build قبل (`3ecfeab`) و بعد در مرورگر Chromium محلی با دادهٔ ثابت API بررسی شدند: تأخیر API برابر ۷۵۰ms، latency برابر ۱۰۰ms، دانلود ۱۸۰KiB/s و کندسازی CPU چهاربرابر. دو اجرای cache خالی برای هر viewport: موبایل ۳۹۰px/DPR2 و دسکتاپ ۱۴۴۰px/DPR1. فایل‌های JS/CSS/JSON در هر دو حالت gzip بودند. درخواست‌های خارجی تصاویر/فونت در این آزمایش مسدود بودند؛ بنابراین این اندازه‌گیری بهبود دسترسی واقعی Google Fonts را عددگذاری نمی‌کند.

دستهٔ صوتی با ۱۰ محصول سناریوی سنجش است. «چهار عکس» زمان کامل‌شدن چهار تصویر اول از شروع navigation است؛ «ده عکس» بعد از eagerکردن همان ده تصویر برای سنجش کل مجموعه اندازه گرفته شد. این عدد Lighthouse، LCP یا آمار کاربران واقعی نیست. جزئیات خام در [گزارش JSON](../docs/performance/2026-11-16.json) است.

| معیار | موبایل قبل ← بعد | دسکتاپ قبل ← بعد |
|---|---|---|
| چهار عکس اول | حدود ۲۲٫۷ ← ۳٫۹ ثانیه | حدود ۲۳٫۳ ← ۳٫۲ ثانیه |
| کل ده عکس | حدود ۲۷٫۳ ← ۶٫۵ ثانیه | حدود ۲۷٫۳ ← ۳٫۷ ثانیه |
| انتقال تصاویر سناریو | حدود ۴٫۶۵ ← ۰٫۶۷ مگابایت | حدود ۴٫۶۵ ← ۰٫۱۶ مگابایت |
| درخواست فهرست محصولات | یک درخواست در هر اجرا | یک درخواست در هر اجرا |

زمان ظاهرشدن خود کارت‌های HTML تقریباً در همان محدودهٔ ۲٫۸ ثانیه مانده است؛ بهبود اصلی در پایان دانلود تصاویر و حذف رقابت عکس‌های فوتر است. نتیجه برای عکس، دستگاه، شبکه و محل سرور دیگر متفاوت خواهد بود. این تغییر خواب Render/Neon یا خرابی API را حذف نمی‌کند و وعدهٔ پاسخ زیرثانیه برای اولین بازدید زنده نیست.

### ساخت، نگهداری و بررسی

از ریشهٔ مخزن، برای افزودن/تعویض **عکس همراه کد** با محیط Pillow تثبیت‌شدهٔ بک‌اند، اسکریپت `scripts/build-store-images.py` را اجرا کنید. در PowerShell:

```powershell
cd D:\nexoraShop\backend
$env:UV_PROJECT_ENVIRONMENT = '.venv-admin'
uv run --frozen python ../scripts/build-store-images.py
```

سپس registry در `src/data/responsive-images.js` و فایل‌های `public/assets/store-images` را با هم ثبت کنید. گزینهٔ `--check` بازتولید و تطابق کامل را بررسی می‌کند. آپلود عادی عکس از پنل از endpoint رسانه استفاده می‌کند و نیاز به اجرای این اسکریپت ندارد.

تبدیل فونت ابزار build جداگانهٔ `scripts/build-web-fonts.py` است؛ fontTools و Brotli فقط برای تولید فونت لازم‌اند و وابستگی runtime جدید نیستند. مجوز OFL همراه فونت‌هاست.

برای تکرار benchmark از ریشه، پس از build:

```powershell
npm run build:vercel
$env:NEXORA_CHROME = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
node scripts/check-performance.mjs --label current
```

این ابزار فقط GET به سرور fixture موقت محلی می‌زند و تغییری در حساب/دادهٔ واقعی نمی‌دهد. مسیر خروجی JSON در پوشهٔ temp سیستم است. آرگومان `--root` امکان سنجش build جدا و `--label` نام گزارش را مشخص می‌کند.

بررسی این تغییر: lint و build، آزمون‌های منطق فرانت و تصاویر، مرورگر همهٔ دسته‌ها در شش عرض با تم روشن/تیره و کنترل alpha، فیلتر، navigation، جزئیات، و تست پشتیبانی موفق بودند. این‌ها جای smoke test دیپلوی واقعی و بررسی شبکهٔ کاربر را نمی‌گیرند.
