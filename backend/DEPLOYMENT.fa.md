# استقرار رایگان FastAPI، PostgreSQL و فرانت‌اند Vercel

فرانت‌اند روی Vercel باقی می‌ماند. بک‌اند روی Render Free و دیتابیس روی Neon Free
اجرا می‌شوند. ساخت حساب‌ها و انجام مراحل زیر لازم است؛ این فایل‌ها به‌تنهایی
سرویس آنلاین ایجاد نمی‌کنند.

## دیتابیس

در [Neon](https://neon.com/) یک پروژه با پلن **Free** و دیتابیس خالی مخصوص Nexora
بسازید. از Connect آدرس PostgreSQL را بگیرید؛ نمونهٔ قالب:

```text
postgresql://USER:PASSWORD@HOST/neondb?sslmode=require
```

همان URL واقعی، همراه پارامترهای TLS، فقط در متغیر `DATABASE_URL` سرویس بک‌اند
قرار می‌گیرد. آن را در گیت، کد فرانت‌اند یا پیام عمومی نگذارید.

## بک‌اند

پس از push آخرین تغییرات، در Render گزینهٔ **New → Blueprint** را بزنید و ریپو
را انتخاب کنید. فایل `render.yaml` از ریشهٔ ریپو خوانده می‌شود:

- سرویس `nexora-api` از `backend/Dockerfile` با پلن **Free** ساخته می‌شود.
- مقدار `DATABASE_URL` را از Neon وارد کنید.
- `SECRET_KEY` خودکار تولید می‌شود؛ آن را در دیپلوی‌های بعدی حفظ کنید.
- مقدار `ENVIRONMENT=production` کوکی‌های امن را فعال می‌کند.

قبل از شروع سرور، Alembic جدول‌ها را می‌سازد و محصولات اولیه وارد می‌شوند.
آدرس HTTPS سرویس، مانند `https://YOUR-SERVICE.onrender.com`، را بردارید.
`/health` و `/api/products` آن را بررسی کنید؛ دومی باید آرایهٔ JSON بدهد.
هیچ دیسک یا دیتابیس پولی برای این مسیر لازم نیست؛ پلن Free را انتخاب کنید.

## اتصال Vercel

در Environment Variables پروژهٔ فرانت‌اند قرار دهید:

```text
NEXORA_API_ORIGIN=https://YOUR-SERVICE.onrender.com
```

آخر آدرس `/api` نگذارید. آخرین commit را deploy کنید. Root Directory باید ریشهٔ
ریپو باشد، نه `src`، `dist` یا `backend`. سپس روی دامنهٔ اصلی `/api/products`،
`/api/csrf`، ثبت‌نام، ورود و خروج را امتحان کنید. پاسخ 401 برای `/api/auth/me`
قبل از ورود طبیعی است؛ پاسخ 404 یا HTML به معنی اشکال در دیپلوی است.

## محدودیت‌های رایگان

طبق [مستندات Render](https://render.com/docs/free)، سرویس Free بعد از ۱۵ دقیقه
بی‌کاری می‌خوابد و بیدار شدن ممکن است حدود یک دقیقه طول بکشد. درخواست اول ممکن
است ناموفق شود؛ پس از بیدار شدن، تلاش مجدد کنید. این مسیر برای دمو مناسب است
و تضمین دسترس‌پذیری یک فروشگاه تجاری را نمی‌دهد.

فایل‌های محلی Render پایدار نیستند؛ اطلاعات و نشست‌های ورود در Neon ذخیره
می‌شوند. از دیتابیس رایگان خود Render استفاده نمی‌کنیم، چون طبق مستندات فعلی
بعد از ۳۰ روز منقضی می‌شود. [Neon Free](https://neon.com/docs/introduction/plans)
هم سقف مصرف دارد؛ پیش از ساخت سرویس شرایط فعلی را بررسی کنید.

## ورود گوگل و داده‌های قدیمی

یک Google OAuth Client از نوع Web بسازید، آدرس Vercel را در Authorized JavaScript
origins اضافه کنید و Client ID را در `GOOGLE_CLIENT_ID` سرویس Render قرار دهید.
بدون آن، ورود با ایمیل و رمز عبور فعال است ولی ورود گوگل فعال نیست.

نسخهٔ ASP.NET و دیتابیس محلی آن در `backend/legacy/Nexora.Api` باقی مانده‌اند.
Alembic داده‌های قبلی SQLite را خودکار منتقل نمی‌کند. اگر حساب یا سفارش مهمی
در نسخهٔ قبلی دارید، انتقال داده و رمزهای عبور باید جداگانه انجام شود.
# بازیابی رمز عبور

در تنظیمات Environment سرویس بک‌اند Render این متغیرها را اضافه کنید:

- `RESEND_API_KEY`: کلید خصوصی سرویس Resend؛ فقط روی بک‌اند قرار بگیرد.
- `MAIL_FROM`: آدرس فرستنده از دامنهٔ تأییدشده در Resend، مانند `Nexora <accounts@your-domain.com>`.
- `FRONTEND_URL`: آدرس فرانت‌اند، مانند `https://nexora-digital-shop.vercel.app`، بدون مسیر اضافی.

پس از تنظیم، بک‌اند و فرانت‌اند را دیپلوی کنید. اجرای `start.py` مهاجرت `0002` را اعمال می‌کند.
تا پیش از تنظیم ایمیل، فرم بازیابی پیام عدم دسترسی به ارسال ایمیل نشان می‌دهد.
برای تست محلی، همین متغیرها را در `backend/.env` قرار دهید و `FRONTEND_URL=http://localhost:3000` بگذارید.
Docker Compose فایل `.env` بک‌اند را خودکار وارد کانتینر نمی‌کند؛ برای تست ارسال در Docker این متغیرها را در محیط سرویس `api` تنظیم کنید.
حساب‌هایی که فقط با گوگل ساخته شده‌اند باید از گزینهٔ «ادامه با گوگل» استفاده کنند.
